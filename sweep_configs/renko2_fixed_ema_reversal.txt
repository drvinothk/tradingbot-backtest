#   not two independent ones. Rather than force two thresholds onto one

#   single width axis spanning both the "tight target" (2-3) and "wider
#   SL" (3-4) framings the user gave -- the backtest itself shows which
#   width trades off cut-losers-fast vs. give-trades-room better, rather
#   than guessing a combined rule. See renko_trend.py's own
#   `_reversal_structure_level` -- it is already an exact price level (N
#   bricks against the held direction from the live box), not an
#   approximation, so this is a real test of the idea as stated.
# - ema_timeframe_minutes is set equal to brick_source_timeframe_minutes
#   for every config (EMA(30) computed on the same chart the bricks are
#   built from -- the most literal reading of "use EMA 30 crossover" with
#   no separate timeframe given).
# - TSL: fixed at trail_activation_fraction=0.5 / trail_lock_fraction=0.6
#   (the user's own numbers) for every config in this batch, not swept --
#   the user said "I don't know if we should have TSL," which read as
#   wanting a recommendation, not a sweep axis; applying it uniformly is a
#   safe default (it only ever locks in MORE profit than doing nothing,
#   never widens risk) and keeps the grid from doubling again. Flag if you
#   want a with/without-TSL comparison added as a follow-up.
# - target_pct=0.60 / stop_pct=0.35 (generous premium ceiling / spec's own
#   25-35% floor) stay as a background dual-layer safety net so a config
#   still exits if the underlying-level reversal signal somehow lags
#   (e.g. an IV move not yet reflected in brick count) -- same "exit on
#   whichever hits first" principle every strategy here already follows,
#   not a new behavior.
